# primitive_db

Учебный проект — примитивная база данных, которая работает в консоли.

Программа умеет создавать и удалять таблицы со столбцами типов `int`, `str` и `bool`,
добавлять, читать, обновлять и удалять записи (CRUD), фильтровать их по условию `where`
и красиво выводить результат в виде таблицы. Структура таблиц хранится в файле
`db_meta.json`, данные каждой таблицы — в папке `data/` в формате JSON.

## Структура проекта

```
src/primitive_db/
├── main.py         # точка входа
├── engine.py       # главный цикл, разбор команд пользователя
├── core.py         # логика: таблицы и CRUD-операции
├── parser.py       # разбор условий where/set и значений values
├── utils.py        # работа с файлами (метаданные и данные таблиц)
├── decorators.py   # декораторы и кэширование через замыкание
└── constants.py    # константы
```

## Управление таблицами

Команды:

- `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` — создать таблицу.
  Столбец `ID:int` добавляется в начало автоматически.
- `list_tables` — показать список всех таблиц.
- `drop_table <имя_таблицы>` — удалить таблицу.
- `help` — справочная информация.
- `exit` — выход из программы.

Поддерживаемые типы данных: `int`, `str`, `bool`.

Информация о таблицах (имена и столбцы) хранится в файле `db_meta.json`.

Пример использования:

```
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table users
Таблица "users" успешно удалена.
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
```

## CRUD-операции

Команды для работы с данными внутри таблиц:

- `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` — создать запись.
  Значение `ID` не передаётся, оно генерируется автоматически.
- `select from <имя_таблицы>` — прочитать все записи.
- `select from <имя_таблицы> where <столбец> = <значение>` — прочитать записи по условию.
- `update <имя_таблицы> set <столбец> = <новое_значение> where <столбец_условия> = <значение_условия>` — обновить запись.
- `delete from <имя_таблицы> where <столбец> = <значение>` — удалить запись.
- `info <имя_таблицы>` — вывести информацию о таблице.

Правила записи значений:

- строки пишутся **в кавычках**: `"Sergei"`;
- целые числа — как есть: `28`;
- логические значения — `true` / `false`.

Все поля обязательные. Данные каждой таблицы хранятся в отдельном файле
`data/<имя_таблицы>.json`.

Пример:

```
>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".
>>>Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.
>>>Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".
>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

## Обработка ошибок, подтверждение действий и замер времени

Повторяющаяся логика вынесена в декораторы (`decorators.py`):

- `handle_db_errors` — перехватывает ошибки (несуществующая таблица или столбец,
  неверный тип значения, отсутствующий файл) и выводит понятное сообщение
  вместо падения программы:

  ```
  >>>Введите команду: select from users where city = "Moscow"
  Ошибка: Таблица или столбец 'city' не найден.
  >>>Введите команду: insert into users values ("Bob", "20", true)
  Некорректное значение: 20. Попробуйте снова.
  ```

- `confirm_action` — перед опасными операциями (`drop_table`, `delete`) спрашивает
  подтверждение. Если ответить не `y`, операция отменяется:

  ```
  >>>Введите команду: delete from users where ID = 1
  Вы уверены, что хотите выполнить "удаление записи"? [y/n]: n
  Операция отменена.
  ```

- `log_time` — показывает время выполнения `insert` и `select`:

  ```
  Функция select выполнилась за 0.000 секунд.
  ```

Результаты одинаковых запросов `select` кэшируются с помощью замыкания `create_cacher`.
